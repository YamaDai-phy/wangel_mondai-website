# ワンゲル過去問データベース 運用説明書

## 1. システムの構成

このサイトは、次のCloudflareサービスを利用しています。

| 用途 | サービス | 名前・URL |
| --- | --- | --- |
| Webサイト | Cloudflare Pages | `https://wangel-mondai.pages.dev` |
| アップロード・審査API | Cloudflare Workers | `pdf-upload-api` |
| PDF保存 | Cloudflare R2 | `pdf-storage` |
| 投稿情報・公開状態 | Cloudflare D1 | `wangel-papers` |
| 管理者への通知 | LINE Messaging API | WorkerのSecretで設定 |

サイトのファイルは `site/`、Workerのプログラムは `worker/` にあります。

## 2. PDF投稿を処理する

### 投稿者が行うこと

1. `https://wangel-mondai.pages.dev/fileupload` を開きます。
2. 種別、科目、PDF、投稿者名を入力します。
3. 「送信する」を押します。

送信されたPDFはR2へ保存されます。この時点では一般公開されません。

### 管理者が行うこと

1. LINEに届いた「確認・公開」リンクを開きます。
2. 投稿情報とPDFプレビューを確認します。
3. 問題がなければ「公開する」を押します。
4. 不適切な投稿なら「却下する」を押します。

「公開する」を押すと、D1の状態が公開済みに変わり、PDF一覧へ自動的に表示されます。ファイルをPCへダウンロードしたり、Gitへ追加したりする必要はありません。

「却下する」を押すと、D1の状態が却下済みに変わり、R2上のPDFが削除されます。一度処理した確認リンクは再利用できません。

### 未完成品の場合

1. 投稿者は種別で「未完成品」を選んで送信します。
2. PDFはR2の `incomplete/` 配下へ保存され、一般公開されません。
3. 管理者のLINEには編集用PDFのリンクだけが届きます。
4. 公開・却下の承認操作はありません。
5. 管理者がPDFを編集します。
6. 完成後、「問題」または「答え」として改めてアップロードします。

未完成品は公開一覧やファイル制作者一覧には表示されません。

## 3. 公開後に確認する

1. `https://wangel-mondai.pages.dev/pdf` を開きます。
2. 公開したタイトルが正しい科目欄に表示されることを確認します。
3. 「リンク」を押し、PDFが表示されることを確認します。
4. 資料室の「ファイル制作者一覧」に投稿者名とタイトルが表示されることを確認します。

一覧への反映には最大約1分かかる場合があります。

## 4. Gitのブランチ

| ブランチ | 用途 |
| --- | --- |
| `main` | 通常の開発・保管 |
| `cloudflare-deploy` | Cloudflare Workerの本番デプロイ |

Cloudflare Workers BuildsのProduction branchには `cloudflare-deploy` を指定します。Workerの変更を本番へ出す場合は、このブランチへ反映してpushします。

```powershell
git switch cloudflare-deploy
git pull
git merge main
git push origin cloudflare-deploy
```

競合が表示された場合は、無理にpushせず内容を確認してください。

## 5. WorkerとGitHubを接続する

Cloudflare Dashboardで以下を設定します。

1. 「Workers & Pages」を開きます。
2. Worker `pdf-upload-api` を選びます。
3. 「Settings」→「Builds」→「Connect」を開きます。
4. GitHubリポジトリ `YamaDai-phy/wangel_mondai-website` を選びます。
5. Production branchを `cloudflare-deploy` にします。
6. Root directoryを `worker` にします。
7. Build commandを `npm run check` にします。
8. Deploy commandを `npx wrangler deploy` にします。
9. Production branch以外のビルドを無効にします。
10. Watch pathsを設定できる場合は `worker/**` を指定します。

設定後は、`cloudflare-deploy` の `worker/` に変更がpushされるとWorkerが自動デプロイされます。

## 6. D1の構造を変更した場合

`worker/migrations/` にSQLファイルを追加した場合は、Workerをデプロイする前にマイグレーションを実行します。

```powershell
cd worker
npm install
npm run check
npm run db:migrate:remote
```

確認画面が表示されたら、適用する内容を確認してから続行します。通常のプログラム変更だけなら、この操作は不要です。

## 7. 手動でデプロイする

GitHub自動デプロイが使えない場合は、次のコマンドでWorkerを更新できます。

```powershell
cd worker
npm install
npm run check
npm run deploy
```

Webサイトを手動で更新する場合は次を実行します。

```powershell
cd worker
npx wrangler pages deploy ../site --project-name wangel-mondai --branch main
```

## 8. 秘密情報

次の値はGitHubへ保存してはいけません。

- `LINE_CHANNEL_ACCESS_TOKEN`
- `LINE_USER_ID`
- Cloudflare API Token
- `.dev.vars`、`.env` に記載した値

本番用のLINE設定はCloudflare WorkerのSecretとして保存されています。値を更新する場合は `worker/` で次を実行します。

```powershell
npx wrangler secret put LINE_CHANNEL_ACCESS_TOKEN
npx wrangler secret put LINE_USER_ID
```

## 9. トラブル対応

### 投稿後にLINEが届かない

- Cloudflare DashboardでWorkerのログを確認します。
- `LINE_CHANNEL_ACCESS_TOKEN` と `LINE_USER_ID` が設定されているか確認します。
- LINE Botが通知先へメッセージを送信できる状態か確認します。

### 「確認リンクが無効または処理済みです」と表示される

すでに公開または却下されています。同じリンクは再利用できません。

### 公開したPDFが一覧に出ない

- 約1分待ってからページを再読み込みします。
- `https://pdf-upload-api.yamadai.workers.dev/papers` を開き、対象データがあるか確認します。
- D1の投稿状態が `published` になっているか確認します。

### PDFが開かない

- R2の `pdf-storage` に対象オブジェクトがあるか確認します。
- WorkerのR2 bindingが `PDF_BUCKET`、バケットが `pdf-storage` になっているか確認します。

### Workerの更新に失敗する

ローカルで次を実行し、テスト結果を確認します。

```powershell
cd worker
npm install
npm run check
npx wrangler deploy --dry-run
```

## 10. バックアップについて

- R2にはPDF本体が保存されます。
- D1にはタイトル、投稿者、科目、公開状態などが保存されます。
- GitHubにはサイトとWorkerのプログラムが保存されます。

GitHubへpushしても、R2のPDFやD1の投稿データは削除・変更されません。
